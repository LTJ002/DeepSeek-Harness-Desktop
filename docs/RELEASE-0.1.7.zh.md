## 0.1.7 更新内容

### 启动可靠性

- **孤儿内核检测与清除**——内核过滤条件缺陷（打包安装下 `bin.js` + `--profile web` 恒不命中）让应用漏掉上次强杀残留的内核并直接复用，加载旧 `node_modules` 快照生成的 bundle（`rev` 哈希每次启动都锁死，即「Failed to load plugins」）；现过滤条件已修正，父进程已消失的孤儿内核一律杀除、不复用
- **白屏根因修复**——每次服务重启都会下发新的 `dsh-auth-*` cookie，浏览器全部保留（一个月堆积 70 个）；窗口携带全部 cookie 请求导致认证失败，服务端返回空 `text/plain` 页面。现连接前自动清理历史认证 cookie，只保留最新的一个
- **窗口 URL 缓存击穿**——每次加载窗口附带时间戳参数，不再命中引用旧 bundle `rev` 的缓存 HTML 快照
- **MCP 运行时路径自动校正**——stdio 型 MCP 的 `command` 若指向旧安装路径（`...\resources\runtime\node.exe`），启动时自动校正为当前安装位置（应用搬盘 / 重装后 MCP 不断链）

### 内核

- 内核升级至 **0.1.5-rc.1**（官方 npm）：支持会话日志 v3 格式（回滚 / 删除 / 修复作用于内核真正读取的文件，找回 3 个此前不可见的会话）、MCP 客户端更新与适配器修复
- **模型名修正**：`DeepSeek-V41-Flash` → `DeepSeek-V4.1-Flash`（上游文案笔误，运行内核与发布包同步修正）

### 插件安装 / 更新

- **Bundle 冲突预检**——启用 bundle 插件前，检查其 `cordis.patch.yml` 的条目 id 是否与现有 bundle 树冲突（如重复的 `code-runtime`）；冲突时拒绝启用并说明原因，不再以 `duplicate loader entry id` 崩溃启动
- **启动自愈**——每次启动扫描当前 bundle 列表，自动移除冲突条目；配置即使已被写坏也能自行恢复
- **卸载无残留**——卸载时同步移除该插件的离线预装副本（此前副本会被「离线预装」路径在下次启动悄悄复制回 profile——这正是卸载的插件反复回来的原因），并清理空的 scope 目录
- **Registry 自动回退**——官方 npm 源出现网络类错误（超时 / 连接重置 / DNS / 证书）时，自动切换 npmmirror 镜像重试一次（此前更新检查用镜像、安装用官方源，国内网络下会出现「检查有更新、安装却失败」）
- **启动失败自动回滚**——每次安装 / 更新成功后记录变更快照；若应用随后 30 分钟内冷启动失败（装后软验证漏过的不兼容），自动回滚该变更（更新→恢复旧版本；新装→卸载）并重试启动一次
- 安装包**不预装任何插件**（`preloaded-plugins` 为空）、默认插件自动安装名单清空，不再静默安装或装回

### 恢复与诊断

- **AI 诊断优化**——把已尝试过的修复方案（action / env / command）一并交给模型，3 轮修复不再重复同样的无效建议；模型给出的危险环境变量（`NODE_OPTIONS`、`NODE_PATH`、`PATH`、`LD_PRELOAD` 等）一律拦截（提示词注入防御）
- **bundle 冲突检测合并**为单一 `findBundleConflicts` 核心（安装预检 / 更新预检 / 启动自愈共用）；全量引用计数核验死代码为 0

### 归档与回滚

- **回滚归档界面**——回滚会话时移出的「本轮新建文件」（存于 `~/.dsh/rollback-trash`，保留目录结构与元数据）现可在回收站页列出并一键恢复到原位置（含跨卷复制回退）
- 回滚时的文件移动失败不再静默：跨卷自动回退为复制+删除，失败的文件如实上报，同批已归档的文件绝不因清理被误删
- 检查点 / 回滚分区英文模式补全

### 插件与 MCP

- **应用内 MCP 服务器管理**——在「设置 → 插件与 MCP」直接添加 / **编辑** / 删除 MCP 服务器（不再需要手改 `cordis.patch.yml`，也不依赖本机装有 Claude Code / opencode）：支持 stdio（命令 + 参数）与 streamable-http（URL + **Headers**），**改完自动热重载、立即生效**
- **「装什么都变成系统插件」判定修正**——只有真内核组件（`@deepseek-ai/*`、少数裸核心依赖、设置页插件自身）才显示「系统」；用户自己安装的 bundle 插件（如 `toto-the-cat`）恢复卸载入口
- 「已安装插件」页的系统组件**默认折叠**（点击展开）——约 200 行内核依赖不再淹没你自己的插件

### 其他

- **完成音效修复**——插件安装 / 更新 / 卸载完成提示音恢复（解除 Chromium autoplay 限制 `autoplay-policy=no-user-gesture-required`，并加 AudioContext resume 兜底；提示音在窗口重载后播放，此前因无用户手势被静默拦截）
- **英文模式译文补齐**——所有 `t()` 键均有英文条目（此前若干回退中文）；检查点、回滚、归档、插件市场与 MCP 界面的裸写中文全部包裹并翻译
- 版本显示口径：桌面端 0.1.7 / 内核 0.1.5-rc.1（两者独立编号）
