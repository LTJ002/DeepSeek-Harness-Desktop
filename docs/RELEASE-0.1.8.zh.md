## 0.1.8 更新内容

### 插件安装可靠性

- **静态导入预检**——插件在重启内核做装后验证**之前**，先在隔离沙箱（`node_modules` junction）中做一次真实导入。若插件引用了内核已不存在的导出（如 `@deepseek-ai/dsh-settings` 的 `installSettingsSection`——内核升级后的常见故障），立即回滚，内核全程不崩溃、**安装期间会话保持可用**（此前内核加载此类插件时反复崩溃退出，应用在自动回滚完成前无法使用）
- **装后软验证加固**——软验证（重启内核后检查页面）此前会把 Chromium 错误页（"无法访问此网站"）当作验证通过：内核崩溃在页面文本中没有留下插件失败标记，于是插件被报告为安装成功，直到下次冷启动才回滚。现在验证同时识别 Chromium 错误页文案、探测本地服务 API 存活、并要求 3 秒稳定窗口——启动数秒后才崩溃的内核不再能蒙混过关
- **自动回滚可见**——启动因最近安装 / 更新的插件失败时，自动回滚会登记为一条可见任务；任务面板与右上角提示会报告（含插件名与回滚动作），不再静默移除插件

### 内核

- 内核升级至 **0.1.5-rc.2**（官方 npm）：反馈提交（点赞 / 点踩）改为弹窗确认后提交、失败保留已填内容；交付文件卡片排版、对话间距与代码文件图标优化
- `DeepSeek-V41-Flash` → `DeepSeek-V4.1-Flash` 模型名修正在 rc.2 内核升级后重新应用（官方内核包每次升级都会带回该笔误）

### Web profile

- profile 的全部 200 个 `@deepseek-ai/*` 依赖与内核同步升级至 **0.1.5-rc.2**（不再 rc.1 / rc.2 混跑）

### 构建

- 内置版本 **0.1.8**——`app.asar` 与 `exe` 版本元数据同步
