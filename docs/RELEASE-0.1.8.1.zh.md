## 0.1.8.1 更新内容

插件安装安全加固版。内核保持 **0.1.5-rc.2** 不变——本次更新全面加固桌面端的插件安装 / 更新链路。

### 插件安装安全

- **静态导入预检**——插件在重启内核验证**之前**，先在隔离沙箱中做真实导入。引用了内核已不存在的导出（如 `@deepseek-ai/dsh-settings` 的 `installSettingsSection`——内核升级后的常见故障）的插件会被立即回滚：**内核全程不崩溃，安装期间会话保持可用**（此前内核加载此类插件时反复崩溃退出）
- **装后软验证加固**——软验证此前会把 Chromium 错误页（"无法访问此网站"）当作验证通过，导致不兼容插件被报告为安装成功、直到下次冷启动才回滚。现在验证会识别错误页文案、探测本地服务 API、并要求 3 秒稳定窗口
- **自动回滚可见**——启动因最近安装 / 更新的插件失败时，自动回滚会在任务面板与右上角提示中报告（含插件名与回滚动作），不再静默移除插件

### 插件更新防御

- **内置插件保护**——内置桌面插件（含提供「插件市场 / MCP / 归档管理 / 更新」分区的设置插件）不再会被回滚或清理流程移除。修复了「更新 cordis 失败后回滚把整个包卸载、并连带把设置插件移出加载列表」导致这些分区消失的问题
- **设置插件自毁防御**——设置插件的修复流程在 profile 使用 `link:` 依赖时不再有清空自身源目录的风险（同源检测 + 符号链接感知删除 + 源目录非空校验三重防御）
- **bundles 冲突自愈保护**——启动时的 bundle 冲突自愈只移除用户侧条目，内置条目绝不自动移除

### 更新防误点

- **跨预发布线不再提示更新**——已装稳定线（如 `0.1.5-rc.2`）时，alpha 线版本（如 `0.1.6-alpha.2`）不再显示为「可更新」（rc/alpha 组件混装是已知的启动崩溃诱因）
- **更新入口拦截**——即使触发更新，跨预发布线或构成降级的目标也会被拒绝安装（显式指定精确版本仍按用户意图放行）

### 修复

- AI 诊断路径的回滚补传「安装前版本」（此前可能"恢复"到刚刚装上的新版本）
- 本地 `file:` 依赖（兼容 shim）不再被误报为可更新——此前点击更新会覆盖本地修复
- `DeepSeek-V41-Flash` → `DeepSeek-V4.1-Flash` 模型名修正在 rc.2 内核升级后重新应用

### 构建

- 内置版本 **0.1.8.1**——`app.asar` 与 `exe` 版本元数据同步
